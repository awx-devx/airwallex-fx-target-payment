# 09 — Decisions & Open Questions

## Decisions (ADR-lite)

Status values: **Proposed** (default, open for objection), **Accepted**, **Superseded**.

| ID | Decision | Status | Rationale / alternatives |
| --- | --- | --- | --- |
| D-01 | Monorepo-less single Next.js app + separate Node **worker** process sharing `src/` | Accepted | Simplest to demo and deploy. Alternative: Turborepo with `apps/web`, `apps/worker`, `packages/*`. Can be split later without code changes thanks to the boundary rules. |
| D-02 | **MongoDB + Mongoose** as the database; **Redis** for BullMQ queues and pub/sub fan-out | Accepted | Team choice. Redis is needed: MongoDB has no job queue or cross-process push. Timers live in Mongo and a sweeper enqueues BullMQ jobs, which keeps the warp clock and restart catch-up simple. MongoDB runs as a replica set, which transactions require. See [02 §9](./02-architecture.md#9-mongodb--redis-conventions). |
| D-03 | Execute through **one `transfers/create` call with `quote_id`** (conversion inside the transfer) | Accepted | Works for buy-only currencies (INR, PHP, …) and gives one idempotency key and one status stream. V4 and V9 passed on 2026-10-04 for EUR and INR. V3 also accepted `POST /fx/conversions/create`; that path stays unused. See [01 §3.2](./01-feasibility-airwallex.md#32-buy-only-currencies--execute-through-a-single-transfer-not-conversion-then-payout). |
| D-04 | "Convert now, pay on due date" is **out of scope for the demo**. Pay immediately when the target is hit, or at the deadline cutoff. | Accepted | V7 accepted `quote_id` with `transfer_date` on 2026-10-04. The demo still pays at the target hit or at the cutoff. |
| D-05 | Trigger on **indicative** rates and pay on a **quote** re-checked against the target | Accepted | The worker locks a binding price and pays in the same job. A near miss keeps watching. |
| D-06 | Approval runs **in our app**, not through Airwallex transfer approvals | Superseded | Superseded by D-23. Airwallex approval-submitted transfers still cannot use quotes; that constraint stays in D-23. |
| D-07 | Deadline guarantee = in-app scheduler (Layer A). The Airwallex scheduled-transfer safety net (Layer B) sits behind a flag. | Accepted | V6 created a future-dated transfer with `lock_rate_on_create=false`, fee 0, and cancel succeeded. Layer B stays behind the flag. |
| D-08 | Standing instruction consent is **required to arm** a bill | Accepted | That consent, given once at submit, authorizes both the target-hit payment and the deadline payment. The bill is still paid by its deadline. |
| D-09 | Canonical price = `sell_amount / buy_amount` (H per F) from the CLIENT level | Accepted | Avoids `currency_pair` orientation bugs. |
| D-10 | Display pair `F/H`, lower = better; auto-offer inversion when price < 0.01 | Accepted | Consistent "buy low" mental model for the target line. |
| D-11a | Animation runs through **Motion** (`motion` on npm, formerly Framer Motion); CSS keyframes only for `glow-pulse` and skeleton shimmer | Accepted | One timing system, layout animations and reduced-motion support for free. Spec: [05 §6](./05-design-system.md#6-motion). |
| D-11 | Charts use TradingView Lightweight Charts v5 + custom series primitives | Accepted | Performance + price lines built in. Alternative: ECharts/visx (heavier or more work). |
| D-12 | UI kit rendered on our own `/dev/ui-kit` page (no Storybook) | Accepted | Stays in the app's real theme/runtime and is faster to set up. The showcase configs can later generate Storybook stories. |
| D-13 | Hybrid demo mode: simulated market + real sandbox quotes/transfers | Superseded | Superseded by D-29. Quotes and transfers stay real sandbox calls. |
| D-14 | History backfill from Frankfurter (ECB) behind `HistorySource`, with the ECB data API when Frankfurter fails | Accepted | Free and keyless. The chart opens on about 90 days of daily fixings; the Airwallex rate is the current point, not the start of the line. A pair neither host publishes still shows own ticks. Paid intraday feeds (Open Exchange Rates, Twelve Data) stay out. |
| D-15 | Bill extraction: deterministic readers (e-invoice XML, payment QR, text layer) + **Claude via the Anthropic API** (structured outputs, Haiku → Sonnet escalation) + validators + mandatory human review. Optional local Ollama adapter; `mock` for tests | Accepted (model defaults pending the B4.2b benchmark) | Airwallex OCR is web-app only. Claude reads PDFs natively (text + page images) and returns schema-valid JSON without a GPU, so it fits the single server. Local VLMs need a GPU and are weaker on scans. Spec: [12](./12-bill-extraction.md). |
| D-16 | Demo "Simulate" button: per-bill scripted price path → normal trigger → real sandbox quote → real sandbox transfer → driven to Paid (~26 s) | Accepted | One-click target-hit beat on stage, while the rest of the terminal can stay on the live feed. The ticks go into the normal auto-execute path. The GBP bill stays watching. Spec: [08 §1.1](./08-demo-plan.md#11-simulate-button). |
| D-17 | Seeded test-data generator (Faker + our PRNG; invoices rendered from React templates with Playwright; `sharp` for scanned variants) with profiles, pooled sandbox beneficiaries, and states reached only through real services | Accepted | Smooth, reproducible testing without hand-made fixtures. No fake Airwallex IDs, so sandbox data stays consistent. The same generators feed the mock `DataSource`. Spec: [11](./11-test-data-and-seeding.md). |
| D-18 | Bills are paid in full: `fee_paid_by: PAYER` and, for SWIFT, `swift_charge_option: PAYER` (Airwallex default is `SHARED`, which lets intermediary banks deduct from what the vendor receives) | Accepted | An invoice is settled only if the vendor receives the invoiced amount. V17 priced it at create time: on a 20 EUR SWIFT transfer, `PAYER` was fee 25 (payer pays 47.66) and `SHARED` was fee 15 (payer pays 37.66). Spec: [13 §4.1](./13-airwallex-contracts.md#41-request-fields-we-set-post-apiv1transferscreate). |
| D-19 | Contracts for Airwallex data follow the Airwallex API reference field by field (enums verbatim, lossless amounts, one mapper for Retrieve responses and webhook `data.object`), and `transfers/validate` runs at arming | Accepted | The UI kit can build every Airwallex-driven variant (statuses, funding, failures, verification, schema forms) before integration, and corridor or reference errors surface in review instead of at trigger time. Spec: [13](./13-airwallex-contracts.md). |
| D-21 | Bill extraction progress shows a **ThinkingOrb** (`thinking-orbs`, [libraries.dev/orbs](https://libraries.dev/orbs)) instead of the generic spinner | Accepted | Extraction is the one place a model is working, and the orb's states map onto the pipeline stages. It ships with no runtime dependencies. Spec: [07 §2](./07-pages-spec.md#2-upload--review-flow-upload-also-a-modal-over-the-terminal). |
| D-20 | UI primitives use **Radix** (`radix-ui`), icons use **Lucide**, dates use **date-fns** | Accepted | Already the stack in [02 §2](./02-architecture.md#2-stack-defaults-see-09) and [05 §8](./05-design-system.md#8-iconography--illustration). Headless Radix keeps focus trapping; Lucide is the 1.5 px icon set; date-fns counts business days for the date picker. |
| D-22 | The page ground is a bottom **grain aurora**: Paper Shaders `GrainGradient` (`@paper-design/shaders-react`, pinned `0.0.81`) | Accepted | WebGL2, no Three.js. A softened wave in dimmed violet and orange on `--bg-0`, masked into the bottom 40vh, paused under reduced motion. Mesh, warp, smoke, and rays were tried on the kit and dropped. Spec: [05 §2](./05-design-system.md#grain-aurora). |
| D-23 | A submitted bill is **paid automatically**. The standing instruction at submit authorizes a target hit and the deadline payment. Airwallex's transfer-approval workflow stays off | Accepted | One person uploads, reviews, and submits. A target hit and the cutoff each lock a short quote and create the transfer in the same job. Supersedes the in-app approval half of D-06. Airwallex approval-submitted transfers cannot use quotes, so that workflow stays disabled. |
| D-24 | Airwallex response bodies are parsed with **`lossless-json`** | Accepted | Amounts arrive as JSON numbers. `JSON.parse` rounds past ~15 significant digits, so numbers are kept as decimal strings before `decimal.js`. Specified in [13 §1](./13-airwallex-contracts.md#1-wire-conventions). |
| D-25 | Deadline instants use **`date-fns-tz`** | Accepted | [02 §2](./02-architecture.md#2-stack-defaults-see-09) already named it beside `date-fns`. The cutoff is a wall-clock time in `AIRWALLEX_ACCOUNT_TZ`, including across DST. |
| D-26 | Domain property tests use **`fast-check`** | Accepted | B3.1 asks for property tests of the rate math. It is a dev dependency. |
| D-27 | Extraction readers use **pdfjs-dist**, **@napi-rs/canvas**, **zxing-wasm**, and **fast-xml-parser** | Accepted | [12 §2](./12-bill-extraction.md) names them: pdf.js for the text layer and embedded XML, canvas for page renders, zxing for EPC and Swiss QR, and fast-xml-parser for Factur-X and UBL. Claude is called with `fetch`, so there is no Anthropic SDK. |
| D-28 | Anthropic extraction is capped at **20 calls per hour** in a Redis window | Accepted | A page sent as a document block costs a few thousand input tokens. The cap is shared by the web process and the worker (`EXTRACTION_MAX_CALLS`, `EXTRACTION_WINDOW_SEC`). A full window refuses the upload and the call. `0` turns the cap off for a benchmark. SHA-256 cache hits, `mock`, and `ollama` do not count. Spec: [12 §2.3](./12-bill-extraction.md#23-claude). |
| D-29 | The demo market feed is Airwallex sandbox `rates/current` (`RATE_SOURCE=airwallex`). Simulate is a recorded per-bill switch. `RATE_SOURCE=simulated` stays for offline development and mock mode | Accepted | A shared random walk made every bill look simulated and could trigger a payment on a price the sandbox quote would not match. The top bar shows feed health. A bill's chart reads Simulated only after Simulate is pressed on that bill. Supersedes the simulated-market half of D-13. Spec: [08](./08-demo-plan.md). |
